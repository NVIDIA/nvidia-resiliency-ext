# L2 Evidence Grounding And Identity

L2 checks whether a usable L1 assessment is credibly tied to evidence the model
could see. It derives a client-owned root identity from a grounded primary and,
independently, an observation-only identity from a grounded selected
observation. It emits advisory audit findings without replacing the model's
semantic opinion.

`SCHEMA.md` owns exact field shapes. `L3.md` owns history comparison. L2 does
not select policy.

L2 ends at grounded current-attempt facts, enriched identity, and advisory
findings; history comparison and action policy belong to L3-L4.

## Purpose And Authority

```text
L0Bundle
  + exact L0ModelFacingView
  + L1EvidenceResult and tool transcript
  + immutable source snapshot
  -> source grounding
  -> route primary and observation AttemptFailureFacts
  -> advisory audit
  -> L2Result
```

L2 has two responsibilities with different authority:

1. **Functional grounding and identity.** Resolve the model-selected primary
   and non-primary observations independently. Derive a stable root fingerprint
   only from a grounded primary and a separate observation fingerprint only
   from a grounded selected observation. Either or both route tracks may exist.
2. **Advisory audit.** Report citation, causal-role, and semantic credibility
   concerns. Findings are observational only: they do not overwrite L1, change
   route usability, or influence L3/L4.

This split keeps the model's answer visible while preventing invented or
unseen evidence from silently entering history or policy.

## Public Result Boundary

L2 never rewrites the public `l1_assessment` block. Its compact public output is
`l2_grounding`, which contains:

- whether L2 ran and the independent grounding/publication status of each
  primary and observation track;
- the grounded primary, grounded observed failures, selected grounded
  observation, and grounded related failures;
- citations accepted as grounded evidence;
- an explicit declaration that audit findings are observational only;
- independent primary/root and observation identities with their explicit
  identity kinds;
- grounding adjustments and findings grouped by primary or observation track.

Detailed citation audits and field diagnostics remain in the trace. This keeps
the public result reviewable without duplicating the full trace.

## Inputs And Output

| Direction | Contract | Meaning |
| --- | --- | --- |
| Input | `L0Bundle` | Complete deterministic evidence and object relationships. |
| Input | `L0ModelFacingView` | Exact initial evidence visible to the model. |
| Input | `L1EvidenceResult` | Parsed `semantic_payload`, raw transcript, and tool results. |
| Input | `LogSnapshot` | Immutable source used for line and quote resolution. |
| Output | `L2Result` | Grounding status, enriched facts, and observational audit diagnostics. |

L2 runs only for structurally usable L1 output. Otherwise it reports `not_run`
and the deterministic branch continues. L1 owns response-contract validation;
L1 removes unknown response extensions before publishing its canonical semantic
payload. L2 does not further normalize that payload or repair a
contract-invalid response.
L2 does resolve observation `evidence_ids` against canonical evidence. An
undefined ID is recorded as `dangling_evidence_reference` and omitted from the
grounded citation projection without modifying raw L1. L2 audits these
references for every observation, including observations the model did not
select. Only a selected observation may still ground through its explicit line
when that line exists and was visible to the model.
Duplicate object IDs are retained as L1 contract advisories and do not block
independent line grounding. A `selected_observed_failure_id` must resolve to exactly one
observation before L2 can publish that track. Zero matches produce
`selected_observation_id_unresolved`; multiple matches produce
`selected_observation_id_ambiguous`. Either finding disables only the
observation track, while an independently grounded primary remains usable.
Recovery citation completeness is deliberately an L2 concern: a usable L1
response may omit a recovery support tag without losing its grounded primary or
grounded selected observation.

## Grounding Rules

Model-visible evidence is the union of:

- the exact full initial `model_visible_payload`, including the deterministic
  failure narrative and compact Decision Evidence view,
  attempt execution context, and evidence bundle;
- all returned advertised-tool payloads in the conversation.

A provenance line number alone does not make arbitrary source text visible.
Canonical support requires the line and paired rendered text or quote.
Source existence and model-visible support are separate L2 facts. A primary or
observed failure is grounded only when its source line exists and paired text
was visible in L0B or a successful tool result, or when a visible quote uniquely
resolves to a nearby source line. Source existence alone is diagnostic and
cannot authorize enriched failure facts.

Citation resolution statuses are:

- `exact`: line and quote match the source;
- `rendered_exact`: quote exactly matches the visible client rendering,
  including a truncation marker;
- `abbreviated_exact`: a model-authored quote contains an explicit ellipsis and
  at least two substantial literal fragments that occur in order on both the
  same source line and its model-visible rendering; it never changes the cited
  line and produces `audit_status=resolved`;
- `nearby_resolved`: the visible quote maps uniquely to one nearby source line;
- unresolved/ungrounded: no unique credible mapping exists.

Mechanical repair is deliberately narrow. L2 may correct a small line-number
error when the quote was visible and uniquely identifies a nearby source line.
It cannot invent support, rewrite the quote, or substitute a semantically
preferred source line.

## Enriched Failure Tracks

For each grounded primary or selected observation, L2 creates an independent
route-keyed `AttemptFailureFacts` block:

- the primary track uses `identity_kind=root` plus a client-derived
  `root_fingerprint` and source;
- the observation track uses `identity_kind=observation_only` plus a
  client-derived `observation_fingerprint` and source;
- both use source `l2_grounded` and retain their own anchor provenance;
- client-observed `fault_outcome`;
- selected primary/root lines on the primary track or selected observation line
  on the observation track;
- failure iteration when observed;
- optional grounded `affected_entity`;
- explicit locality when it belongs to the selected root, and rank-to-GPU
  mapping.

L1's `failure_identity` remains a semantic description in the raw L1 result; it
is never copied into history. If the L1-selected line belongs to the same
canonical incident as the L0 primary, L2 reuses the L0 observed failure class
and root identity. If L1 selects a different grounded incident, L2 uses a
source-derived generic failure class and derives the enriched root identity
from that incident's source evidence. It does not promote free-form model
mechanism text into a client-owned failure class or fingerprint.
L0 root-observer locality is reused only for `same_canonical_incident`. For a
different grounded incident it is unavailable unless that selected root gains
its own source-derived occurrence association.

L2 never copies an observation value into `root_fingerprint`, even when no
primary is available. The runtime inserts or replaces both track slots under
the route id in the current `AttemptRecord`. Shared progress remains the
L0-derived record field. Grounding one track never suppresses or overwrites the
other.

### Root Fingerprint

The fingerprint identifies the initiating failure family/mechanism selected as
primary for history and policy. It is derived from the grounded source
observation, not from free-form model class text. It excludes rank, node, GPU,
timestamp, cycle id, and source line. It is null when no primary is grounded;
two null roots are never comparable.

### Observation Fingerprint

When one selected observation is grounded, L2 derives
an `observation_fingerprint` from that source occurrence or normalized group.
It uses the same volatile-field exclusion as root identity but is marked
`identity_kind=observation_only` and `policy_active=false` by default. Matching
observation fingerprints establish only that the same failure surface was
visible. They do not establish the same initiating cause and do not feed L3's
root or root-plus-entity ledgers.

An explicitly declared L4 policy context may consume an observation signature
when that context defines the full match and retry behavior. Generic L2 does not
promote the observation identity for that purpose.

### Failure Objects And Affected Entity

L2 grounds two independent model-proposed paths against the complete
model-visible source payload:

- `direct_failure_object_path`: the exact object on which the failing operation
  directly acted;
- `affected_artifact_path`: the enclosing workload artifact being consumed or
  produced.

For each primary or selected-observation track, `grounded_failure_identities`
reports the model value, grounded value, source lines, and grounding status for
both fields. Null or ungrounded values remain explicit; L2 never infers one path
from the other.

For a grounded primary, L2 selects the optional `artifact` affected entity in
this order:

```text
if affected_artifact_path is grounded:
    affected_entity = affected_artifact_path
else if direct_failure_object_path is grounded:
    affected_entity = direct_failure_object_path
else:
    affected_entity = unavailable
```

The enclosing artifact is preferred because it describes the workload object
whose operation failed. The direct object is an exact fallback when the model
cannot support that enclosing relationship. L2 does not relabel the direct
object as a model-proposed artifact or infer a parent path. The public
`affected_entity_selection` records the chosen source field, selection reason,
grounding lines, and resulting typed entity. L3 and L4 consume only that typed
entity.

Entity identity is separate from failure mechanism. The exact path is hashed
without removing its distinguishing components. Source-code locations,
traceback frames, component installation paths, log paths, and diagnostic
callsites are provenance rather than failure objects or affected entities.
Contract clarification at L1 is the first guard against that confusion; L2
still requires each proposed runtime path to appear in model-visible source
evidence.

If neither the model-selected primary nor selected observation is grounded, L2
may preserve usable L1 semantics for observability but leaves enriched failure
facts and identities unavailable. This includes a real source line whose text
was not model-visible, as well as an invented line. Neither can match a prior
attempt through the enriched branch.

## Recovery-Assessment Audit

L2 checks whether the evidence tags attached to L1 recovery fields resolve to
model-visible source evidence. The result is a support observation, not a
policy-eligibility decision. Missing or unresolved support may produce a
finding, but it does not suppress, normalize, reject, or reinterpret the L1
field.

When the L1 response is structurally usable, the exact typed L1 recovery
assessment is retained beside the route. It applies to the primary track when a
primary is grounded. It applies to the observation track only when L1 reported
no primary; otherwise the observation is fallback evidence without a separate
semantic recovery assessment. An observation-only assessment may select only
the root-independent general rule unless a declared policy context explicitly
matches it. For example,
`hypothesis_only` and `unknown` remain weaker policy inputs because of their
status, not because L2 rejected them. If neither anchor is grounded, the
enriched branch is unavailable and policy uses the deterministic branch.

## Advisory Audit

L2 may report:

- missing, duplicate, unseen, or unresolved citations;
- primary/related-failure causal-role inconsistencies;
- unsupported path ownership or persistence claims;
- same-attempt rank fanout incorrectly treated as cross-attempt recurrence;
- failure position described as completed progress without a completed marker;
- same-artifact or same-physical-unit observations that weaken a claim;
- alternative interpretations with `applied=false`.

Findings carry severity and `observational_only=true`. They remain visible in
the result and trace without changing result quality, NVRx eligibility, route
selection, history, retry policy, or action.

L2 audit status is:

- `clean`;
- `resolved` for permitted mechanical reference repair;
- `findings`;
- `not_run`.

Grounding status is independently `grounded`, `unavailable`, or `not_run`.
The route-level aggregate is `grounded` when at least one track is published;
per-track status remains authoritative for L3 availability.

## Invariants

- Raw L1 semantic output is immutable and remains traceable.
- L2 never changes model confidence.
- Audit findings never become hidden policy inputs and never degrade a route.
- L4 consumes the exact typed L1 recovery assessment for the track to which L1
  attached it; L2 supplies track identities but does not select policy.
- Enriched identity is client-derived from grounded source evidence.
- Observation identity never populates the root fingerprint or root-scoped
  recurrence ledgers.
- A primary with causal role `cascade` or `teardown` is ineligible for grounding
  even if its source line and quote resolve. This is a defensive boundary for an
  invalid L1 contract payload, not semantic correction of the raw response.
- Related cascade/teardown events remain observational and are excluded from
  `secondary_failures` when that would make them look like competing roots.
- L2 does not read or mutate attempt history.
- L2 does not emit `STOP`, `RESTART`, retry budgets, or `decision_basis`.

## Degraded Behavior

- Unusable L1 output produces `not_run`; no repair is attempted in L2.
- A structurally valid `no_failure_observed` result produces
  `grounding_status=unavailable` with no enriched failure facts; it is not an L1
  execution failure.
- A structurally valid `insufficient_evidence` result may still produce
  observation-only enriched facts when its selected observation is grounded.
- A selected observation with dangling evidence references remains groundable
  from its explicit model-visible source line; the dangling references remain
  visible as observational findings.
- An unresolved or ambiguous selected observation is withheld without erasing
  a separately grounded primary. Public `track_findings` records which track
  was affected.
- An ungrounded primary leaves enriched history identity unavailable.
- A usable but ungrounded L1 result is traced as attempted but not used; the
  deterministic L0 branch remains eligible.
- Partially grounded citations preserve the raw L1 answer and explicit
  findings; no missing support is synthesized.
- A missing recovery support tag cannot erase a grounded primary, affected
  entity, history identity, or recovery field.
- Audit failure cannot erase the deterministic recommendation.
- Tightening audit into a blocking semantic validator requires an explicit
  contract or configuration change and corpus evidence.

## Tracing

The L2 trace records:

- exact visibility inputs used for grounding;
- raw model-selected primary and citations;
- citation resolutions and mechanical adjustments;
- grounding and audit statuses;
- functional enriched failure facts;
- root or observation fingerprint, identity kind, and affected-entity source;
- identity lineage relative to the L0 deterministic primary;
- recovery-support observations;
- findings, severity, and unapplied suggestions;
- L2 wall time.

## Service Logging

L2 emits one INFO completion event per route:

```text
event=restart_agent.l2.completed route_id=<id> status=<status>
wall_clock_s=<seconds> grounding_status=<status>
primary_track=<grounded|unavailable|not_run>
observation_track=<grounded|unavailable|not_run>
root_fingerprint_source=<source|unknown>
observation_fingerprint_source=<source|unknown>
affected_entity_ready=<bool> audit_status=<status>
observational_findings=<count>
```

`status` is `completed` when grounding/audit ran, `not_run` when the canonical
L2 trace explicitly records that state, and `not_available` only when no L2
stage record exists. It is execution state, not a judgment about L1 semantics.

DEBUG emits `restart_agent.l2.detail` with grounding method, resolved and
unresolved reference counts, advisory finding counts by kind, and the
non-sensitive family/concrete identity readiness flags. It does not emit raw
source quotes, model text, or complete fingerprints.

## KPIs

| Quality KPI | Example |
| --- | --- |
| Primary grounding accuracy | Model line 12084 is uniquely repaired to visible quote at 12083. |
| Citation resolution accuracy | A quote absent from all model-visible inputs remains ungrounded. |
| Fingerprint availability | A grounded terminal failure produces a root identity; an invented line does not. |
| Fingerprint stability | Different models selecting credible lines in the same episode derive the same root fingerprint. |
| Observation-fingerprint accuracy | A grounded selected TCPStore reset produces an observation-only identity, while no root fingerprint is synthesized. |
| Track co-availability accuracy | A valid primary plus grounded selected observation publishes both tracks without invalidating either. |
| Identity-kind separation | Root and observation-only facts never leak into one another's fields or history scopes. |
| Affected-entity accuracy | A grounded enclosing checkpoint is preferred; otherwise an exact grounded lock file becomes the entity without inferring its parent. |
| Recovery-support audit precision | Missing support is reported without changing the L1 field or L4 policy input. |
| Audit precision | Findings identify real review concerns without rejecting or degrading semantically valid output. |

Operational metrics include:

- L2 wall time and status;
- primary/observation grounding and publication status;
- citation counts by resolution;
- mechanical adjustment count;
- observational findings by severity;
- enriched root/observation/entity readiness and source;
- recovery-support audit coverage.

## Example

L1 selects line 12084 and quotes a decode exception visible at line 12083.
L2 finds one unique nearby match and records:

```text
grounding_status: grounded
grounding_method: nearby_resolved
primary line: 12083
root fingerprint: observed:unicodedecodeerror:checkpoint_metadata
affected entity: artifact:/checkpoint/step_100
audit_status: resolved
```

The L1 semantic assessment remains unchanged. L3 receives the enriched
fingerprint/entity through the current `AttemptRecord`; L4 later decides how
that evidence affects policy.
