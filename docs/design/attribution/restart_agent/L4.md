# L4 Restart Policy

L4 is the only stage that selects an evidence path and emits `STOP` or
`RESTART`. It consumes typed current failure tracks and their matching L3
histories; it does not parse logs, revise L1 semantics, construct identity, or
persist state. `SCHEMA.md` owns exact fields, while this document owns policy
behavior.

## Stage Contract

```text
CycleFailureEntry + CycleHistoryComparison
  -> select eligible primary, observation, deterministic, or none
  -> base rule + declared policy context
  -> retry ledgers + shared job guard
  -> STOP | RESTART
```

| Direction | Contract | Policy use |
| --- | --- | --- |
| Input | `CycleFailureEntry` | Deterministic facts plus route-keyed grounded primary and observation facts. |
| Input | route recovery assessments | Exact typed L1 failure domain and unchanged-workload retry outlook. It belongs to the primary when one exists, otherwise to the selected observation. Confidence is retained but is not a threshold. |
| Input | `CycleHistoryComparison` | Matching deterministic/primary/observation histories plus shared job progress. |
| Input | retry configuration | Allowed retries for base policies and the job guard. |
| Input | declared policy contexts | Trusted policy information supplied outside the log. |
| Output | `L4PolicyOutcome` | Selected evidence path, policy selection, ledger evaluations, decision basis, and recommendation. |

## Evidence-Path Selection

L4 selects one path for the current recommendation without deleting the other
tracks from history or observability:

```text
if eligible grounded primary exists:
    selected_path = primary
else if eligible grounded selected observation exists:
    selected_path = observation
else if eligible deterministic facts exist:
    selected_path = deterministic
else:
    selected_path = none
```

The selected track is paired only with its L3 history. L4 never combines a
primary with observation recurrence or a model-grounded fact with deterministic
recurrence. With multiple routes, route arbitration must be explicit in the
runtime/configuration contract; completion order is not preference.

When L1 returned a primary, its recovery assessment belongs to that primary.
If that primary is unavailable but the same response has a grounded
observation, the observation path may still provide root-independent retry but
must not inherit primary-specific domain/recovery semantics. When L1 returned
no primary, its assessment may accompany the selected observation under the
observation-only restrictions below.

## Retry Configuration

`allowed_retries` counts retries after the first observed failure. A value of
`1` restarts the first occurrence and stops on the next qualifying occurrence.

| Setting | Default | Scope |
| --- | ---: | --- |
| `concrete_confirmation_retry_allowed_retries` | 1 | Same root and exact entity |
| `workload_confirmation_retry_allowed_retries` | 1 | Grounded workload failure and same root |
| `general_retry_allowed_retries` | 2 | Same-root budget when root identity exists; same-job no-progress budget for observation-only general retry |
| `job_no_progress_allowed_retries` | 3 | Same job, independent of root and entity |
| `job_unknown_progress_allowed_retries` | 3 | Same job with progress that cannot be compared |

The default-enabled `cuda_oom_no_retry` context supplies a zero-retry policy.
The default-enabled `port_bind_confirmation_retry` context supplies one
confirmation retry for a terminal address-in-use bind failure, independent of
the model's failure-domain label. The default-enabled
`rejected_iteration_retry_then_skip` context has an
independent two-retry budget configured under `policy_contexts`. Neither
changes the general retry ceiling recorded beside the effective policy.

`policy_version=retry_budget.v1` is behavior provenance, not a caller
configuration field.

## Failure Identity And History

| Concept | Definition | Policy use |
| --- | --- | --- |
| Root fingerprint | Normalized failure mechanism or family | General same-family recurrence |
| Observation fingerprint | Normalized selected failure surface on its own track | Diagnostic recurrence and declared-context matching; never generic root recurrence |
| Identity kind | `root`, `observation_only`, or `none` | Selects which comparison scopes are valid |
| Affected entity | Exact grounded operation-associated object selected by L0 or L2 | Concrete recurrence |
| Full identity | Root fingerprint plus a non-null affected entity | Concrete confirmation policy |
| Same-root streak | Consecutive same-root attempts with no observed advance | General or workload-confirmation ledger |
| Same-root-and-entity streak | Consecutive full-identity matches with no observed advance | Concrete-confirmation or policy-context ledger |
| Job no-progress streak | Consecutive same-job attempts with no observed advance, regardless of failure identity | Non-overridable guard |

A missing root is not a shared unknown identity, and two null roots never
match. A missing entity is unknown, not a value or wildcard, and two null entities
never form a concrete match. For example,
`file_read_failure + /checkpoints/iter_5000/metadata` is a full identity;
the same root with another path belongs to the same family but is not the same
concrete failure.

Progress affects every retryable ledger:

| L3 progress relation | Effect |
| --- | --- |
| `advanced` | Protect the retry and break the applicable no-progress streak. |
| `same` or `regressed` | Consume the applicable retry budget. |
| `unknown` | Consume the separate same-job unknown-progress guard; do not consume a root no-progress ledger. |

## Base Rules

Rules are selected from top to bottom. A matching policy context may supply a
different effective retry policy without changing the recorded base rule.

| Priority | Base rule | Condition | History scope | Retries |
| ---: | --- | --- | --- | ---: |
| 1 | `workload_unrecoverable` | Primary outcome is `terminal` or `unresolved`; `domain=workload` and `retry_outlook=cannot_recover`; both L1 statuses are `established_by_current_log` | None | 0 |
| 2 | `concrete_confirmation_retry` | Full identity available | Same concrete failure | 1 |
| 3 | `workload_confirmation_retry` | `domain=workload` with L1 status `established_by_current_log` or `supported_but_unconfirmed`, and no full identity available | Same failure family | 1 |
| 4 | `general_retry` | Primary/root available and no narrower rule matched | Same failure family | 2 |
| 5 | `general_retry` | Selected path is observation | Same-job no progress; observation recurrence is not treated as root recurrence | 2 |

No base rule is selected when the selected path has neither a primary nor a
selected observation. A deterministic root may still select its applicable
root rule; identity-none uses `no_primary_failure` while unconditional same-job
guards remain active.

The two confirmation rules are deliberately distinct. Concrete confirmation
requires equal non-null entities on both attempts. Workload confirmation does
not compare the entity field; it is a semantic workload rule over the root-only
history ledger when concrete identity is unavailable. Different or missing
entities never count as concrete matches, and different entities do not reset
the concurrent `general_retry` family budget when the root remains the same.

Observation-only `general_retry` is deliberately root-agnostic. Its retry count
comes from L3's consecutive same-job no-progress count. The observation
fingerprint remains visible for diagnosis, stability measurement, and declared
policy-context matching, but it does not create a same-root or concrete ledger.
Different observations therefore cannot reset the observation-only general
budget while the job continues to make no progress.

## Declared Policy Context

A declared policy context supplies information that is unavailable from the
log. It is applied only when its typed signature matches:

| Context part | Responsibility |
| --- | --- |
| Current matcher | Match typed current failure facts without parsing logs. |
| History matcher | Select qualifying L3 comparisons and count recurrence. |
| Policy override | Supply behavior, history scope, and allowed retries. |

```text
base_rule = select_base_rule(current_facts, typed_l1_assessment)
policy_context = match_declared_policy_context(current_facts)
effective_policy = policy_context.retry_policy if policy_context else base_rule.retry_policy
```

L4 records both the base rule and any applied policy context. Context handlers may
consume typed L0-L3 facts, but may not add patterns, change L3 semantics,
reparse the log, mutate history, or emit the final recommendation. Multiple
simultaneous policy-context matches remain unsupported until precedence is defined.

| Example context | Matched log signature | External policy information | Effective policy |
| --- | --- | --- | --- |
| `cuda_oom_no_retry` | CUDA OOM | Product policy treats OOM as inherent to the workload | 0 retries |
| `port_bind_confirmation_retry` | Terminal address-in-use bind failure | Process recreation or restart delay may clear a stale listener, but one recurrence without progress exhausts the confirmation budget | 1 retry |
| `rejected_iteration_retry_then_skip` | Rejected nonfinite iteration with one root observer and a known iteration | Workload retry-then-skip recovery is enabled | 2 retries |

The context changes policy, not the observed failure or L1 assessment. Both the
base rule and applied context remain visible in the result.

### `cuda_oom_no_retry`

This policy context expresses a product choice: a selected terminal CUDA
allocation failure indicates insufficient observed workload memory headroom,
so the agent does not spend a restart even though process teardown could change
the next allocation state.

| Context part | Required signature |
| --- | --- |
| Current attempt | Selected primary is grounded as `failure_class=cuda_oom` or preserves `classifier=cuda_oom`, and has `fault_outcome=terminal` or `unresolved` |
| Progress handling | An earlier CUDA OOM followed by progress is not the selected terminal OOM and does not match |
| History matcher | None |
| Retry policy | `cuda_oom_no_retry`; 0 retries |

The typed classifier recognizes stable CUDA allocation forms such as
`CUDA out of memory`, `CUDA error: out of memory`,
`torch.cuda.OutOfMemoryError`, and `CUBLAS_STATUS_ALLOC_FAILED`. Diagnostic
advice that merely names a CUDA allocation error is not a match. The context is
enabled by default and can be disabled through
`policy_contexts.cuda_oom_no_retry.enabled`.

### `port_bind_confirmation_retry`

This policy context separates operational retry policy from uncertain causal
ownership. An address-in-use failure proves that the selected listener could
not bind, but it does not prove whether the conflicting listener belongs to
the workload, orchestration, or another local service.

| Context part | Required signature |
| --- | --- |
| Current attempt | Selected primary preserves `classifier=port_bind_conflict` and has `fault_outcome=terminal` or `unresolved` |
| Counted prior attempt | Same root fingerprint with no observed progress advance |
| Domain handling | L1 failure domain and retry outlook remain unchanged and do not control this context match |
| Retry policy | `port_bind_confirmation_retry`; 1 retry by default |

The classifier recognizes explicit address-in-use forms such as
`Address already in use`, `EADDRINUSE`, and `Errno 98`. It does not match a
generic connection failure or an ungrounded hypothesis that a port might be in
use. The context is enabled by default; its budget is configured through
`policy_contexts.port_bind_confirmation_retry`.

### `rejected_iteration_retry_then_skip`

This policy context represents a bad token or data window exposed indirectly as a
rejected nonfinite iteration. It aligns with Megatron-LM Rerun State Machine
behavior but does not infer a bad token from `nan_or_inf` alone.

| Context part | Required signature |
| --- | --- |
| Current attempt | `classifier=rejected_nonfinite_iteration`; integer `failure_iteration`; exactly one parsed root-observer rank; zero unattributed root occurrences |
| Counted prior attempt | Same root; same failure iteration; same observer count; same unattributed count; no observed progress advance |
| Rank handling | Observer rank identity may change across attempts |
| Retry policy | `retry_then_skip`; 2 retries |

```text
current_match =
    rejected_nonfinite_iteration classifier
    and failure_iteration is available
    and len(root_observer_ranks) == 1
    and unattributed_root_occurrence_count == 0

if current_match:
    select rejected_iteration_retry_then_skip immediately

for prior in newest_same_root_no_advance_attempts:
    count prior only when iteration and observer facts match current_match
```

The first qualifying failure and one matching recurrence return `RESTART`; the
third qualifying failure returns `STOP`. A changed iteration consumes none of
this context's history budget. Missing or mismatched history does not demote a
valid current match: the context remains selected with zero consumed retries.
Missing iteration, multiple root observers, or unattributed root occurrences
prevent the current context match and use the base policy instead. Unknown
progress does not consume this root-scoped ledger.

The failure iteration is a policy-context-specific history key, not an affected
entity. Only root occurrences contribute to observer facts; cascades, rank
copies, and teardown do not. L0-L3 remain generic:

| Stage | Generic contribution |
| --- | --- |
| L0 | Nonfinite classification, failure iteration, root-observer ranks, unattributed root count |
| Current-fact assembly | Preserve those observations for deterministic and enriched branches |
| L3 | Same-iteration and same-observer relationships for each same-root comparison |
| L4 policy context | Apply the complete signature and context-specific retry ledger |

The context is enabled by default and can be disabled or assigned a different
retry budget through `policy_contexts.rejected_iteration_retry_then_skip`.

## Decision Order

The two job guards are evaluated once for every attempt. They are independent
of primary, root, entity, base rule, and policy context. The general same-root
ceiling remains active beside any narrower selected-policy ledger.

For observation-only `general_retry`, the selected-policy ledger uses
`consecutive_same_job_no_advance_attempts` and
`general_retry_allowed_retries`. The separate job guard remains the
non-overridable outer ceiling. Observation recurrence is recorded but does not
choose or consume either ledger.

```text
selected_path = select_path(primary_tracks, observation_tracks, deterministic)
selected_facts = selected_path.facts
selected_history = history.for_path(selected_path)

effective_policy = resolve_policy(selected_facts, applicable_l1_assessment)
selected_ledger = evaluate_effective_policy(effective_policy, selected_history)
general_ceiling = evaluate_same_root_ceiling(selected_history)
no_progress_guard = evaluate_same_job_no_progress(history.job_progress)
unknown_progress_guard = evaluate_same_job_unknown_progress(history.job_progress)

if effective_policy?.allowed_retries == 0:
    STOP / workload_unrecoverable
else if any_applicable_ledger_observed_advance:
    RESTART / observed_advance
else if no_progress_guard.exhausted:
    STOP / job_no_progress_budget_exhausted
else if unknown_progress_guard.exhausted:
    STOP / progress_unverifiable_budget_exhausted
else if selected_ledger.exhausted or general_ceiling.exhausted:
    STOP / retry_budget_exhausted
else if selected_path is none or effective_policy is none:
    RESTART / no_primary_failure
else:
    RESTART / effective_policy_available
```

Neither job guard can be overridden by a policy context. Each default allowance
of three retries stops the fourth consecutive qualifying same-job attempt. The
unknown guard bounds repeated analysis uncertainty without describing unknown
progress as no progress.

## Policy Invariants

| Invariant | Result |
| --- | --- |
| Grounded primary and observation both exist | Select the primary; retain and compare the observation independently. |
| Primary unavailable, grounded observation exists | Select the observation before deterministic fallback. |
| Enriched tracks unavailable | Select deterministic facts when eligible. |
| Selected path | Use only the matching L3 history; never borrow another track's recurrence. |
| No primary, grounded selected observation | Select root-independent `general_retry`; use same-job no-progress accounting. |
| No primary and no selected observation | Skip failure-dependent policy; same-job guards still apply. |
| Matching observation fingerprints | Never consume a generic root or concrete ledger. |
| Zero-retry effective policy | `STOP`; progress cannot override established nonrecoverability. |
| Retryable policy plus observed advance | `RESTART / observed_advance`. |
| Unknown progress | Root no-progress ledgers are not consumed; the bounded unknown-progress guard is consumed. |
| L1 `unknown` or `hypothesis_only` claim | Retained as returned and cannot select a narrower semantic rule. |
| L2 audit finding | Observable only; cannot change policy selection or route usability. |
| Exhausted job guard | `STOP`; a policy context cannot override it. |
| Missing or empty log | Handled before L4 as `RESTART / log_unavailable`. |
| Provider or L1 failure | Use the deterministic candidate. |
| Scheduler wall-time event | Ordinary evidence; scheduler time policy remains outside Restart Agent. |
| L2 audit suggestion | Never silently replaces an L1 value used by L4. |

## Observability

L4 trace and DEBUG data record:

| Group | Fields |
| --- | --- |
| Path selection | selected path, route id, reason, and availability of all three track kinds |
| Policy selection | base rule, policy contexts considered, applied policy context, effective-policy source |
| Evidence | typed L1 values/statuses and affected-entity requirements |
| Ledgers | selected policy, general root ceiling, job no-progress guard, job unknown-progress guard |
| Result | aggregate exhaustion, `exhausted_by`, decision, basis, wall time |

The current INFO event remains compact:

```text
event=restart_agent.l4.completed candidate_kind=<kind> route_id=<id|none>
wall_clock_s=<seconds> selected_path=<primary|observation|deterministic|none>
rule=<rule|none> decision=<STOP|RESTART>
decision_basis=<basis> retry_budget_exhausted=<bool>
general_matching_attempts=<count>
selected_policy_matching_attempts=<count|unknown>
allowed_retries=<count|unknown> exhausted_by=<ledger-list|none>
```

Required logging adds base rule, applied policy context, effective-policy source, and
job-guard state without reproducing the full result payload.

## KPIs

| Quality KPI | Example assertion |
| --- | --- |
| Path-selection accuracy | Grounded primary wins over a coexisting observation; observation wins only when no eligible primary exists. |
| Path/history alignment | A selected primary consumes only its primary history, never observation or deterministic counts. |
| Fallback accuracy | Unavailable enriched tracks select deterministic evidence without erasing route facts from the attempt record. |
| Base-rule accuracy | Established workload/cannot-recover selects `workload_unrecoverable`. |
| General-ledger accuracy | Same-root no-advance failures consume the family budget even when entities differ. |
| Concrete-confirmation accuracy | One prior exact root/entity no-advance failure exhausts the default concrete-confirmation budget; null entities never match. |
| Workload-confirmation accuracy | A qualifying L1 workload failure without full identity uses the root-only one-retry workload budget. |
| Job-guard accuracy | Alternating roots still stop when the same-job no-progress allowance is exhausted. |
| Observation-only policy accuracy | A grounded terminal observation with no primary receives root-independent `general_retry`; its fingerprint does not consume a root ledger. |
| Empty-evidence separation | No primary and no selected observation remains `no_primary_failure` rather than selecting an evidence-dependent rule. |
| Policy-context signature accuracy | Every counted rejected-iteration attempt satisfies the full nonfinite, iteration, observer, and progress signature. |
| Port-bind context accuracy | An explicit terminal address-in-use failure receives one confirmation retry regardless of whether L1 reports workload or unknown domain. |
| Policy-resolution accuracy | A declared policy context changes the effective policy while preserving the base rule. |
| Advancement protection | Later progress produces `RESTART / observed_advance` for a retryable policy. |
| Decision/basis accuracy | Action and basis agree with policy and ledger state. |
| False-STOP rate | Retryable gold cases are not stopped early. |
| Deterministic replay | Identical inputs produce identical L4 output. |

Operational metrics are L4 wall time, rule and policy-context counts, retry-budget
utilization, exhaustion counts, candidate kind, action, and decision basis.

## Examples

| Case | Current facts and history | Result |
| --- | --- | --- |
| Established workload defect | Grounded workload; cannot recover; both claims established | Immediate `STOP / workload_unrecoverable` |
| Ambiguous permission failure | Grounded enclosing artifact, or exact failed lock object when no enclosing artifact is available | First failure uses `concrete_confirmation_retry`; exact no-progress recurrence stops |
| Checkpoint decode failure | Same root and checkpoint artifact recur without progress | Exact recurrence consumes the concrete-confirmation budget; a different checkpoint does not |
| CUDA OOM without policy context | Grounded workload; no full identity | `workload_confirmation_retry`; same-family no-progress recurrence stops after one retry |
| Port conflict | Recoverability uncertain; no full identity | `general_retry`; same-family no-progress recurrence consumes its budget |
| Infrastructure or unknown | No qualified tighter rule | `general_retry` |
| Missing initiating event | No primary; one terminal TCPStore disconnect surface is selected | Root-independent `general_retry`; same-job no-progress consumes the budget while observation recurrence remains diagnostic |
| Alternating roots or entities | Effective-policy ledgers do not exhaust, but job makes no progress | Job no-progress guard eventually stops |
| Rejected nonfinite iteration | Complete current signature selects the policy immediately; matching no-progress history consumes it | Two retries, then `STOP`; changing rank alone does not reset the sequence |
