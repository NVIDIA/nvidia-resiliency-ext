# L3 History Comparison

L3 compares every available current-attempt identity track with the matching
track in earlier attempts from the same job. It reports recurrence, affected-
entity relation, progress relation, and consecutive no-observed-advance
streaks. It does not select one track, promote an observation into a root,
choose retry thresholds, or emit an action.

`SCHEMA.md` owns `CycleFailureEntry`, `CycleHistoryComparison`, and
`HistorySummary`. `RUNTIME.md` owns the bounded store. `L4.md` owns path
selection and policy.

## Stage Contract

```text
current AttemptRecord + immutable PriorAttemptView
  -> compare shared job progress once
  -> compare deterministic against deterministic
  -> for each route:
       compare primary against same-route primary
       compare observation against same-route observation
  -> CycleHistoryComparison
```

| Direction | Contract | Meaning |
| --- | --- | --- |
| Input | current `AttemptRecord` | Shared L0 progress plus deterministic and route-keyed primary/observation facts. |
| Input | `PriorAttemptView` | Bounded, immutable, exact-job earlier cycles. |
| Output | `CycleHistoryComparison` | Shared job-progress comparison plus one `HistorySummary` per available identity track. |

For one route, the logical output is:

```text
job_progress
deterministic_history
primary_history
observation_history
```

For multiple routes, primary and observation histories remain route-keyed.
Missing same-route prior facts remain unavailable. L3 does not substitute a
prior deterministic track for a missing enriched track, and route completion
order never becomes route preference.

## Comparison Scopes

| Track | Current identity | Comparable prior identity | Meaning |
| --- | --- | --- | --- |
| Deterministic | L0 root, observation, or none | Prior deterministic identity of the same kind | Recurrence visible without a model. |
| Route primary | L2-grounded root and optional entity | Same route's prior primary root/entity | Recurrence of the model-grounded initiating failure. |
| Route observation | L2-grounded observation fingerprint | Same route's prior observation fingerprint | Recurrence of the same visible failure surface, not proof of the same cause. |
| Job progress | Shared `AttemptProgressSummary` | Every eligible prior cycle's shared progress | Root-independent advancement and bounded no-progress/unknown-progress streaks. |

Root and observation comparisons never cross identity kinds. A deterministic
identity is never compared with a primary or observation from an enriched
route. This preserves provenance and makes model contribution measurable.

## Eligibility

Same-job history is unavailable when history is disabled, `job_id` is empty,
or `cycle_id` is missing/not an integer. An eligible lookup with no prior
records is available-but-empty.

An identity track is independently available only when its current fingerprint
exists. Null fingerprints are absence, never comparable values. A root-bearing
prior track must have the same non-null root fingerprint. An observation prior
track must have the same non-null observation fingerprint. Every comparable
prior record also requires exact `job_id` and a distinct earlier integer
`cycle_id`.

Job-progress comparison remains available when all failure identities are
missing. L3 never creates synthetic job ids, cycle ids, roots, or observations.

## Root And Entity

The root fingerprint asks whether two attempts exhibit the same initiating
failure mechanism. Optional `affected_entity` asks whether they involve the
same exact operation-associated object. L0 may derive it deterministically. L2
prefers a grounded enclosing artifact and otherwise uses the grounded direct
failure object. L3 receives only the typed entity and does not reinterpret its
source. Entity relation is `same`, `different`, or `unknown`.

L3 reports both root-only and root-plus-entity recurrence:

- the root-only count continues across entity changes;
- the root-plus-entity count requires equal non-null entity kind and
  fingerprint;
- missing entities never compare equal and never form a concrete match.

Rank, node, GPU, exact source line, and failure position are comparison
observations, not root identity. Same rank does not imply the same GPU without
a validated mapping.

## Observation Identity

An observation fingerprint says only that the same selected failure surface
was visible. Different initiating causes may produce the same TCPStore
disconnect, process wrapper, or transport timeout. Observation matches
therefore have their own count and consecutive no-advance streak and never
enter root/entity ledgers.

L3 does not decide whether an observation is policy-active. L4 may use a
grounded observation as a root-independent fallback or through an explicitly
declared policy context.

## Progress Comparison

L3 compares the current cycle directly with each earlier cycle; it does not
construct an adjacent trajectory such as cycle 4-to-3, then 3-to-2.

Within one comparison, precedence is:

1. compare `last_completed_step` when both attempts have comparable completed
   training progress;
2. compare `last_checkpoint_step` when both have comparable completed saves;
3. when neither positive-progress dimension is comparable, compare
   `failure_iteration` as a weaker position;
4. retain every dimension and combine the positive-progress dimensions.

| Evidence | Relation |
| --- | --- |
| Positive delta | `advanced` |
| Zero delta | `same` |
| Negative delta | `regressed` |
| Missing, incompatible, or conflicting evidence | `unknown` |

If one positive dimension advances and none regress, the combined relation is
`advanced`; the converse is `regressed`. All comparable dimensions equal means
`same`. Conflicting advance/regress directions remain `unknown`.

Marker counts and within-attempt deltas describe absolute progress but do not
select the cross-attempt relation. Equal/lower markers mean no **observed**
advance, not proof that no unlogged work occurred. Unknown progress is never
converted into no progress.

## Counting And Sequence Boundaries

L3 reports all comparable records and independently computes newest-to-oldest
streaks. `same` and `regressed` count as no observed advance; `unknown` is
counted only by the separate same-job unknown-progress streak.

Root and entity streaks stop at the first root mismatch, required entity
mismatch, nonqualifying prior outcome, observed advance, or unknown progress.
Observation streaks use the same boundaries with observation identity. Shared
job streaks are root-independent.

Retry-budget recurrence counts only prior outcomes `terminal` and `unresolved`.
`retry_pending`, `recovered`, and `progressed_after` do not consume a restart
budget. The current failure is never included in a prior-attempt count.

One prior `(job_id, cycle_id)` counts once within a track. Agreement by several
model routes does not multiply recurrence. Each route has its own comparison;
future route arbitration may choose among them, but L3 does not merge them.

## Root Observer Facts

Root-bearing `AttemptFailureFacts` may retain:

- `root_observer_ranks`: distinct parsed ranks that emitted the root
  occurrence; and
- `unattributed_root_occurrence_count`: root occurrences without a parseable
  rank.

The pair is either unavailable (`null`/`null`) or available together. L3 emits
`same_root_observer_count` and
`same_unattributed_root_occurrence_count` for each same-root comparison. Rank
identity is not compared because assignments may change after restart; only
the cardinalities are compared. Known empty rank arrays therefore match at
cardinality zero, while unavailable values never match.

## Invariants

- Current and prior records are immutable.
- L3 consumes typed facts; it does not reopen logs or model prose.
- Deterministic, primary, and observation tracks are compared independently.
- No cross-kind or cross-route fallback is implicit.
- L3 never copies an observation fingerprint into root identity.
- History never changes semantic failure domain or recovery outlook.
- Same-attempt rank fanout is not cross-attempt recurrence.
- Unknown progress is not stalled progress.
- L3 selects no path, route, retry rule, threshold, budget, or action.

## Degraded Behavior

- A missing track produces an unavailable summary for that track, not a
  deterministic substitution.
- Missing root identity leaves root history unavailable while observation and
  same-job scopes may remain available.
- Incomparable progress produces `unknown`.
- A different entity remains a root-family observation but does not consume a
  concrete streak.
- Store truncation remains explicit in prior-view metadata.

## Tracing And Service Logging

The L3 trace records shared job-progress comparisons and, for each track:
route id, track kind, current identity provenance, eligible/excluded prior
cycles, per-dimension progress values/relations, entity relation, observer
relations, aggregate counts, consecutive streaks, and wall time.

INFO emits one compact completion event for the shared comparison and each
available track:

```text
event=restart_agent.l3.completed track=<deterministic|primary|observation>
route_id=<id|none> wall_clock_s=<seconds> history_available=<bool>
same_job_attempts=<count> matching_identity_attempts=<count>
no_observed_advance_attempts=<count> consecutive_no_advance=<count>
```

DEBUG adds per-prior-cycle relation details without application-log text.

## KPIs

| Quality KPI | Example |
| --- | --- |
| Track isolation accuracy | A route observation is never compared with a deterministic or primary root. |
| Root-match accuracy | Rank/timestamp changes do not split the same mechanism; a different mechanism does. |
| Entity-relation accuracy | The same grounded checkpoint or direct lock object is `same`; another object is `different`; null is `unknown`. |
| Observation recurrence accuracy | Repeated TCPStore surfaces are counted separately and never make root history available. |
| Progress-relation accuracy | Current checkpoint 500 versus prior 400 is `advanced`. |
| Unknown-safety accuracy | Sparse logs without comparable markers remain `unknown`, not stalled. |
| Consecutive-count accuracy | An intervening root, advance, unknown relation, or nonqualifying outcome ends the applicable streak. |
| Cycle deduplication accuracy | Three agreeing routes do not count one prior cycle three times. |
| Route-history availability accuracy | Missing same-route prior facts remain unavailable rather than falling back silently. |

Operational metrics are L3 wall time; prior records considered/excluded;
available deterministic/primary/observation tracks; same-root, same-entity,
same-observation, and progress-relation counts; consecutive streaks; and
availability reasons.

## Example

Current cycle 4 has these facts:

```text
deterministic root = terminal_transport_failure_surface
gpt primary root   = nccl_collective_timeout
gpt observation    = tcpstore_connection_loss
completed step     = 100
```

L3 returns three independent histories. A prior cycle whose deterministic root
matches only the first track contributes only to deterministic history. A prior
GPT primary with the NCCL root contributes only to GPT-primary history. A prior
GPT observation with the TCPStore surface contributes only to GPT-observation
history. The completed-step comparison is computed from the shared progress
record and reused without counting the prior cycle more than once.

L4 can then choose GPT primary, GPT observation, or deterministic evidence in
that order without asking L3 to reinterpret any identity.
